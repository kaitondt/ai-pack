## The rules that override default behaviour

1. **Nothing is specified without a source.** Every requirement, rule, message, default,
   validation and threshold traces to an approved requirement, a recorded decision
   (`DEC-*`), an elicitation record, or an external obligation. Anything else is an
   OPEN QUESTION or a labelled `ASM-*` — never a plausible value written as fact.
2. **An undecided requirement stops the design.** Do everything that does not depend on
   it, then stop and ask. Do not design both branches speculatively.
3. **Assumptions are objects, not adjectives.** `ASM-*`, with an owner, a confirm-by date
   and an impact-if-wrong. An unconfirmed assumption blocks the gate that depends on it.
4. **Nothing enters scope without a requirement.** Not an extra button, not a helpful
   validation, not an audit column. It goes to the change-request backlog.
5. **A baselined document changes only through a change request** (`BL-02`), and design
   changes before code (`BL-03`). A hook enforces the first.
6. **Production changes only through the release process.** A hotfix may skip the queue;
   it never skips the record.
7. **No automatic version bump.** Add a revision-history row only when explicitly told to,
   or when a gate baselines the document.
8. **Deliverable language follows the directory**, never the language of the request.
9. **IDs are permanent.** Never renumber, never reuse, never translate.
10. **Traceability is updated as work happens**, not reconstructed before acceptance.
11. **Expected values in tests come from the specification**, never from what the code
    currently returns.
12. **Commit through `/sdlc-commit`, in `{{profile.commit.format}}`.** Stage files by name;
    never commit a read-only path, a baselined document without its CR, or a secret; never
    `--no-verify`, amend, force or push unless the profile allows it (`GT-01..GT-09`). A hook
    enforces it.
13. **Report honestly.** A failing build is reported failing, with its output. A check that
    could not be run is reported as not run, never as passed. A metric is never improved
    by reclassifying the work behind it.

## Coding standards

Code follows, in this order of authority: the client coding standard
(`{{profile.system.coding_standards}}`), then this project's own rules in
`.claude/rules/project/` (`{{profile.project_rules}}`, added with `/sdlc-rule-register`),
then the stack rules under `.claude/rules/` — `java/`, `typescript/`, `react/`, `sql/`, each
loaded with the files it governs — then `.claude/rules/common/`. A project rule may tighten
the invariant rules (`rules/sdlc/`, security) but never relax them. The `on_edit` hook
formats and lints each file as it is written; fix what it reports in the file, and never
loosen the tool's configuration to pass.
