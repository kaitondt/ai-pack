## The rules that override default behaviour

1. **Intent before code.** Every change belongs to an `INT-*` with observable done-when checks.
   A chat request becomes an intent first, shown to the owner (IF-01, IN-04).
2. **Build only what the intent says.** Good ideas are parked as `IDEA-*`, not built (IF-03).
   That includes your own suggestions.
3. **Ambiguity stops the part that depends on it.** Ask one precise question; do not build both
   branches, do not pick silently (IF-04).
4. **Small slices from a clean checkpoint.** ≤ {{profile.slices.max_files}} files,
   ≤ {{profile.slices.max_changed_lines}} lines, one commit, message starts with the slice ID
   (SS-01..SS-03, SC-05).
5. **Three strikes, then stop.** After {{profile.loop.max_fix_attempts}} failed attempts at the
   same symptom: preserve the attempt on an `attempt/*` branch, return to the checkpoint,
   `/vibe-unstuck` (SS-05).
6. **Seen running, or not done.** Every done-when check executed and observed. Not run is
   reported as not run; failing as failing, with output (VT-01, VT-06).
7. **No phantom packages or APIs.** Verify every new package exists and is the right one;
   verify every API against the installed version, not memory (VT-03).
8. **Never bend a check to go green** — no skipping, deleting, loosening, `any`, swallowing
   (VT-05).
9. **Expected values come from the intent**, never from what the code returns (VT-04).
10. **No secrets in code, tests, docs, logs or prompts.** A hook enforces it (SB-01).
11. **Irreversible commands are run by the human** — reset, clean, force-push, drop, deploy to
    production, publish. A hook enforces it (SB-02).
12. **The server decides.** Validate input and check ownership per resource, server-side
    (SB-03).
13. **Every shortcut is a `DEBT-*`** with a due stage; security debt is due by `mvp` (DL-01, SB-08).
14. **If it matters next session, it is in a file** — `DEC-*`, `DEBT-*`, `BUG-*`, `IDEA-*`,
    STATE.md (SC-04).
15. **The stage changes only through `/vibe-graduate`.** Reality overrides the label upward: a
    public URL or real users means `mvp` security, whatever the profile says.

## The loop and its commands

```
/vibe-intent → /vibe-plan → /vibe-build → /vibe-verify → /vibe-review → /vibe-commit → /vibe-handoff
                                 │ 3 strikes
                                 └─► /vibe-unstuck → /vibe-fix
```

| When | Command |
|---|---|
| Start / end a session | `/vibe-resume` · `/vibe-handoff` |
| What are we building | `/vibe-product` |
| A new feature | `/vibe-intent` → `/vibe-plan` → `/vibe-build` |
| Something is broken | `/vibe-fix` · `/vibe-unstuck` |
| An idea outside the intent | `/vibe-park` |
| Shortcuts and cleanup | `/vibe-debt` |
| Is it safe / good | `/vibe-review` · `/vibe-security-check` |
| Commit outside a slice — a fix, a paydown, a `vibe/` update | `/vibe-commit` (format `{{profile.commit.format}}`) |
| Deploy | `/vibe-ship` |
| Next stage / outgrowing the pack | `/vibe-graduate` |
| Where are we | `/vibe-status` |
| Repeated mistakes | `/vibe-refine-skill` |
| A correction given twice | one line below, or `/vibe-rule-register` for a path-scoped or longer rule |
