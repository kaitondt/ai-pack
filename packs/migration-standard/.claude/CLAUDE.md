## The rules that override default behaviour

1. **Nothing is invented.** Every behaviour, message, validation, default, sort order and
   field length traces to legacy source with a `path:line` anchor, or is raised as a
   SPEC-GAP and asked about. Not "reasonable", not "industry standard" — anchored.
2. **Reproduce, do not improve.** No added validation, no removed validation, no corrected
   typos in messages, no reordered fields, no helpful defaults. Improvements go in Open
   Items as proposals.
3. **Legacy is read-only.** Never write under `{{profile.legacy.root}}` or to anything
   matching `{{profile.constraints.readonly_globs}}`. A hook enforces this.
4. **Blocked features stop the run.** A legacy feature disabled in every code path is
   documented as disabled, marked, and escalated to the user. Never enabled on your own
   judgement.
5. **Frozen data objects stop the fix.** If a root cause is inside a read-only stored
   procedure or a frozen schema, report it and wait for a client decision.
6. **A change request is the only authority for new behaviour**, and only for what its
   text actually says. Everything it does not mention stays anchored to the legacy. It is
   worked documents-first, behind two approvals: the option, then the document diff.
7. **No automatic version bump.** Add a revision-history row only when explicitly told to.
8. **Deliverable language follows the directory**, never the language of the request.
9. **IDs are permanent.** Never renumber, never reuse, never translate.
10. **Traceability is updated as work happens**, not reconstructed later.
11. **Report honestly.** A failing build is reported failing, with its output. A check that
    could not be run is reported as not run, never as passed.

## Coding standards

Target code follows, in this order of authority: legacy parity as the design records it,
the client coding standard (`{{profile.target.coding_standards}}`), then the stack rules
under `.claude/rules/` — `java/`, `typescript/`, `react/`, `sql/`, each loaded with the files
it governs — then `.claude/rules/common/`. The `on_edit` hook formats and lints each target
file as it is written; fix what it reports in the file, and never loosen the tool's
configuration to pass. The legacy tree is never formatted.
