# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

The **hub** for AI Pack: four project-agnostic skill packs (`sdlc-standard`, `migration-standard`,
`pm-standard`, `vibe-standard`) plus Python build scripts that translate them into installable
builds for Claude Code, Codex, Gemini CLI, Antigravity and GitHub Copilot. There is no
application code, test suite or linter — the "code" is Markdown (skills, commands, agents, rules),
JSON (`settings.json` hook registrations) and Python 3 (guard hooks and build scripts).

## Source vs. generated — the key rule

- **Edit only `packs/<pack>/`.** `packs/<pack>/.claude/` is the canonical source for *every* AI,
  not a Claude-only copy; the folder name is historical.
- `claude/`, `codex/`, `copilot/`, `antigravity/` and `gemini/<pack>/` are **git submodules
  generated by the build scripts**. Never hand-edit them — each build empties the directory
  (keeping `.git`) and regenerates it.
- `packs/<pack>/.claude/CLAUDE.md` is a *template* copied into adopting projects, not
  instructions for this repo.

## Commands

```bash
python scripts/build-claude-plugins.py        # → claude/   (marketplace "ai-pack")
python scripts/build-codex-plugins.py         # → codex/
python scripts/build-gemini-extensions.py     # → gemini/<pack>/ (one submodule per pack)
python scripts/build-antigravity-plugins.py   # → antigravity/
python scripts/build-copilot-plugins.py       # → copilot/

python scripts/install-claude-project.py <project-dir> <pack>... [--force] [--dry-run]
python scripts/migrate-project-names.py <project-dir> [--apply] [--docs]   # 1.x → 2.x names
scripts/update-plugins.sh [claude codex ...]  # update installed plugins; DRY_RUN=1 to preview
```

There are no tests. To verify a change, run the affected build scripts and inspect the diff
inside the submodule (`git -C claude diff`, etc.); the Claude build prints per-pack
command/agent/skill counts.

Releasing (per AI): rebuild → commit and push inside the submodule → commit the new submodule
pointer here. Bump the `VERSION` constant in each build script when a change must reach installed
copies. Convention from history: the Claude build is versioned separately (2.x) from all the
others (1.x), and both are bumped together in one release commit
("release Claude 2.5.0, others 1.5.0").

## Pack architecture

Each pack has the same shape: `README.md`, `ADOPTION.md`, `COMMAND-FLOW.md`, `profile/`
(`<pack>.profile.yaml` template, `PROFILE-SCHEMA.md`, `examples/`) and `.claude/` with
`CLAUDE.md`, `settings.json`, `hooks/`, `rules/`, `skills/`, `commands/`, `agents/`.

- **Profile-driven.** Skills never hardcode project values; they use `{{profile.*}}` tokens that
  the pack's spine skill (`sdlc-project`, `mig-project`, `pm-project`, `vibe-project`) resolves
  from the project's profile. Commands, skills and agents all carry the pack prefix
  (`sdlc-`, `mig-`, `pm-`, `vibe-`) in kebab-case.
- **Hooks are per pack** (not shared files) and must stay inactive in repositories without the
  pack's profile. Hook commands in `settings.json` must have the exact form
  `python "$CLAUDE_PROJECT_DIR/.claude/hooks/<name>.py"` — the builds regex-rewrite this into each
  AI's launcher (Claude: `hooks/run-hook.py <profile> <script>`, gated on `.claude/<profile>`
  existing) and the Claude build exits on any other form.
- **Shared invariants** across packs: explicit machine-checkable traceability, change-controlled
  baselines, no invention (every spec needs an anchor or is an open question/labelled
  assumption), no deliverable templates shipped (client templates are registered instead).

## How the builds translate sources

Keep these in mind when writing pack text, because the builds rewrite it:

- **Model policy markers.** Claude-only model/effort guidance is wrapped in
  `<!-- model-policy:claude -->` … `<!-- /model-policy:claude -->`. The Claude build strips just the
  marker lines; every other build replaces the whole block with a "not applicable here" note.
- **Text retargeting** (non-Claude builds): string replacement of `.claude` → `.codex`/`.github`,
  `CLAUDE.md` → `AGENTS.md`/`.github/copilot-instructions.md`, `Claude Code` → product name,
  `CLAUDE_PROJECT_DIR`/`CLAUDE_PLUGIN_ROOT` env vars, and `/sdlc-…` command references → `$sdlc-…`
  for Codex (which ships commands as skills). Write paths and product names literally so these
  substitutions keep working.
- **Plugin install note.** The Claude build injects a path-mapping note into the
  `*-init.md`, `*-profile-check.md` and `*-refine-skill.md` commands, because in a plugin install
  `rules/`, the `CLAUDE.md` template and the profile live under `<plugin root>/templates/` and
  rules must be copied into the project by `/<prefix>-init` (plugins cannot load rules).
  Antigravity and Copilot builds similarly convert rules into project-copied rules/instructions.
- Pack metadata (name, prefix, profile file, description, keywords) is duplicated in a `PACKS`
  list at the top of each build script and in `install-claude-project.py`,
  `migrate-project-names.py` and `update-plugins.sh` — adding or renaming a pack means updating
  all of them.

When adding or removing skills/commands/agents, update the counts in the root `README.md` pack
table.
